# GridMonitor Telegram-бот

Бот моніторингу електромережі через хмару **FSolar**: опитує інвертор і
надсилає в Telegram повідомлення про **зникнення/появу мережі** + заряд батареї.
Працює 24/7 на сервері та зберігає стан у SQLite.

## Команди та меню
Бот має **постійне reply-меню з кнопками** (показується на `/start` і `/menu`):
🔌 Стан · 🔋 Батарея · 📊 Споживання · 🕓 Історія · 🔔/🔕 Підписка.

Команди:
- `/start` — підписатися + показати меню
- `/menu` — відкрити меню з кнопками
- `/status` — поточний стан (мережа + батарея)
- `/battery` — заряд, напруга, струм, напрям і потужність заряджання/розряджання
- `/stats` — потужність споживання зараз і енергія за день/місяць/рік/весь час
- `/history` — останні події
- `/stop` — відписатися

## Швидкий старт

### 1. Створити бота
У Telegram → **@BotFather** → `/newbot` → отримаєте **токен** (`123456:ABC...`).

### 2. Налаштувати `.env`
```bash
cd bot
cp .env.example .env
# відредагуйте .env: токен, логін/пароль FSolar, серійник
```
`ALLOWED_CHAT_ID` можна тимчасово лишити порожнім. Після `/start` бот покаже ваш
chat ID, але не відкриє доступ до стану інвертора. Впишіть ID у `.env` і
перезапустіть бота — після цього він відповідатиме лише дозволеному чату.

### 3. Запустити
**Docker (рекомендовано):**
```bash
docker compose up -d --build
docker compose logs -f
```
**Або без Docker:**
```bash
pip install -r requirements.txt
set -a; . ./.env; set +a        # підвантажити змінні (Linux/macOS)
python src/bot.py
```

Для локального запуску залиште `DB_PATH=bot.db`. Docker Compose автоматично
перевизначає шлях на `/data/bot.db` у постійному томі.

## Деплой (працює всюди завдяки Docker)

| Платформа | Як |
|---|---|
| **VPS** (Hetzner, DigitalOcean…) | `git clone` → `.env` → `docker compose up -d`. Найбільше контролю. |
| **Fly.io / Railway** | Підтримують Dockerfile; задайте змінні оточення в дашборді. |
| **Raspberry Pi** | `docker compose up -d`. ⚠️ Має бути на UPS/захищеному виводі інвертора. |

> ⚠️ **Не хостьте вдома без UPS:** якщо сервер живиться від мережі, він вимкнеться разом зі
> світлом — і ви не отримаєте сповіщення про відключення. Хмарний хостинг надійніший.

## Важливо знати
- **Залежність від звʼязку:** бот бачить відключення, лише поки інвертор шле дані у FSolar.
  Ваш off-grid інвертор на батареї — донгл живиться, але **роутер теж має бути на
  захищеному виводі**, інакше дані не дійдуть до хмари під час відключення.
- **Період:** хмара FSolar оновлюється ~раз на 5 хв — це стеля свіжості; опитуємо кожні 3 хв.
- **Повторна доставка:** невдалі Telegram-повідомлення лишаються у SQLite й повторюються
  кожні 30 секунд, зокрема після перезапуску контейнера.
- **Пороги батареї:** при розряджанні бот сповіщає після переходу нижче 90%, 50% і 25%;
  при заряджанні — після переходу вище 90% і 99%. Пороги не повторюються без нового
  перетину рівня.

## Безпека

- Облікові дані й токен зберігайте лише в `.env`; файл не комітиться й виключений
  із Docker build context.
- Не залишайте `ALLOWED_CHAT_ID` порожнім після початкового визначення ID.
- Контейнер запускається від непривілейованого користувача.
- FSolar endpoint-и не мають стабільного публічного контракту й можуть змінитися.

## Тести
```bash
pip install pytest && pytest bot/tests -q
```
Покривають логіку переходів мережі та мапінг знімка (grid-on/off, SOC). Запускаються в CI
(`.github/workflows/bot-ci.yml`).

## Як це влаштовано
```
src/
  config.py    — змінні оточення
  fsolar.py    — клієнт FSolar (RSA-логін, snapshot, alarms) + parse_snapshot
  detector.py  — правило переходу мережі
  storage.py   — SQLite (підписники, стан, історія, черга доставки)
  bot.py       — команди, полер FSolar і доставник Telegram-повідомлень
```
