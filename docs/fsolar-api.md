# FSolar API — контракт, який використовує Telegram-бот

> FSolar не документує ці endpoint-и як стабільний публічний API. Контракт отримано
> зі спостережень за веб-кабінетом і він може змінитися без попередження.

Базова адреса: `https://shine-api.felicitysolar.com`.

## Автентифікація

`POST /userlogin`

```json
{
  "userName": "<email>",
  "password": "<RSA+base64>",
  "version": "1.0"
}
```

Пароль шифрується RSA PKCS#1 v1.5 публічним 2048-бітним ключем FSolar і кодується
в Base64. Успішна відповідь містить токен у `data.token`. Токен передається наступним
запитам у заголовку `Authorization` дослівно, включно з префіксом `Bearer_`.

Типовий конверт відповіді:

```json
{"code": 200, "message": "...", "data": {}}
```

- `200` — успіх;
- `998` — токен завершився, бот виконує повторний вхід і один раз повторює запит;
- інше значення — помилка FSolar.

Реалізація: `bot/src/fsolar.py` (`encrypt_password`, `FSolarClient`).

## Поточний знімок інвертора

`POST /device/get_device_snapshot`

```json
{
  "deviceSn": "<serial-number>",
  "deviceType": "OG",
  "dateStr": "yyyy-MM-dd HH:mm:ss"
}
```

Ключові поля відповіді:

| Дані бота | Поле FSolar | Примітка |
|---|---|---|
| напруга мережі | `acRInVolt` | AC-in, вольти |
| частота мережі | `acRInFreq` | герци |
| режим роботи | `workModeStr` | наприклад, `Line Mode` або `Battery Mode` |
| заряд батареї | `emsSoc`, резервно `emsSocAvg`/`battSoc` | відсотки |
| напруга батареї | `emsVoltage` | вольти |
| струм батареї | `emsCurrent` | ампери |
| потужність батареї | `emsPowerTotal`, резервно `emsPower` | вати |
| навантаження | `loadPercent` | відсотки |
| поточне споживання | `totalConsumPower` | вати; резервно `loadPower`, `loadPowerConvertion`, `acTotalOutActPower` |
| споживання сьогодні | `eLoadToday` | кВт·год; резервно `tLoadToday` |
| споживання за місяць | `eLoadMonth` | кВт·год; резервно `tLoadMonth` |
| споживання за рік | `eLoadYear` | кВт·год; резервно `tLoadYear` |
| споживання за весь час | `eLoadTotal` | кВт·год; резервно `tLoadTotal` |
| час телеметрії | `dataTimeStr` + `timeZone` | локальний час джерела + пояс, наприклад `UTC+03:00` |
| резервний час | `dataTime` | лише за відсутності придатного `dataTimeStr`; сумісність із мілісекундним epoch |

Бот вважає мережу наявною, якщо `acRInVolt > 50` або `workModeStr` містить `Line`
без урахування регістру. Перший знімок після чистого запуску стає базовим станом і
не створює подію. Наступна зміна створює `gridLost` або `gridRestored`.

Для `emsPowerTotal`/`emsPower` **додатне значення означає заряджання, від'ємне —
розряджання**. Значення в діапазоні ±10 Вт вважається простоєм. Якщо поле потужності
відсутнє, бот обчислює його як `emsVoltage × emsCurrent` зі збереженням знака.
У повідомленні потужність відображається за модулем; напрям указується словами.

Знак перевірено 2026-09-05 у [вебклієнті FSolar](https://shine.felicitysolar.com/assets/indexcopy1.916d8dbd.js):
`batteryPowerGreater0 = emsPower > 0`, а підпис батареї вибирається між `btCharge`
та `btDischarge`. Також підтверджено на живій телеметрії: мережа, PV та генератор
мали нульову потужність, `emsPowerTotal` і `emsCurrent` були від'ємними, SOC падав.
Попередня версія бота помилково трактувала знак навпаки. Відсутність мережі сама
по собі не визначає напрям батареї: можливе заряджання від PV чи генератора.

За спостереженнями, `reportFreq` дорівнює приблизно 300 секундам. Опитування бота
частіше не гарантує свіжіших даних.

### Час телеметрії

Офіційний вебклієнт показує `dataTimeStr` поряд із `timeZone` без перетворення
числового `dataTime`. Бот використовує той самий час джерела: враховує UTC-зсув
у самому рядку, а для рядка без зсуву — поле `timeZone`. Якщо пояс у відповіді
відсутній, використовується налаштований `TIMEZONE` (він має відповідати інвертору).
Далі час нормалізується в UTC для SQLite і перетворюється в `TIMEZONE` для Telegram.
Невідомий явний пояс не підмінюється налаштуванням бота.

`dateStr` у запиті теж формується в `TIMEZONE`, незалежно від системного поясу VPS.
Фіксованої поправки `+5 годин` немає: зсув джерела береться з відповіді, а
`Europe/Kyiv` враховує літній і зимовий час.

Якщо придатного часу немає, бот показує `Оновлено: невідомо` і не оновлює
стан для автоматичних сповіщень. Час запиту не підставляється замість часу
телеметрії. Уже збережена історія не переписується.

Первинні джерела, перевірені 2026-09-05:
[вебклієнт пристрою](https://shine.felicitysolar.com/assets/indexcopy1.916d8dbd.js),
[прив'язка endpoint-а](https://shine.felicitysolar.com/assets/index.4250bfe5.js),
[список часових поясів](https://shine-api.felicitysolar.com/location/list_timeZone).
Семантика числового `dataTime` не підтверджена публічним контрактом; він лишається
резервним варіантом для відповідей без текстового часу.

## Журнал тривог

Клієнт також підтримує `POST /device/device_warring_list`. Відповідь містить записи
в `data.dataList`. Для збою живлення спостерігалися `warnCode: "4"` та
`warringName: "Abnormal Mains Power Supply"`.

Поточний фоновий полер визначає обидва переходи зі знімка інвертора; журнал тривог
не є джерелом Telegram-сповіщень.

## Ручна перевірка

PowerShell 7+:

```powershell
pwsh ./scripts/verify-api.ps1 -UserName you@example.com -DeviceSn YOUR_SERIAL
```

Скрипт безпечно запитує пароль, виконує вхід, отримує знімок і показує останні
тривоги. Не додавайте відповіді API, токени або облікові дані до Git.
