# GridMonitor Telegram-бот

Бот моніторингу електромережі через хмару **FSolar**: опитує інвертор і
надсилає в Telegram повідомлення про **зникнення/появу мережі** + заряд батареї.
Працює 24/7 на сервері та зберігає стан у SQLite.

## Команди та меню
Бот має **постійне reply-меню з кнопками** (показується на `/start` і `/menu`):
🔌 Стан · 🔋 Батарея · 📊 Споживання · 🕓 Історія · ⚡ Відключення · 📈 Графіки · 🔔/🔕 Підписка.

Команди:
- `/start` — підписатися + показати меню
- `/menu` — відкрити меню з кнопками
- `/status` — поточний стан (мережа + батарея)
- `/battery` — заряд, напруга, струм, напрям і потужність заряджання/розряджання
- `/stats` — потужність споживання зараз і енергія за день/місяць/рік/весь час
- `/history` — останні події
- `/outages` — кількість і тривалість відключень за сьогодні та поточний місяць
- `/charts` — графіки заряду і навантаження за 24 години
- `/charts week`, `/charts month` — графіки за 7 або 30 днів; період також можна обрати кнопками
- `/stop` — відписатися

## Швидкий старт

### 1. Створити бота
У Telegram → **@BotFather** → `/newbot` → отримаєте **токен** (`123456:ABC...`).

### 2. Налаштувати `.env`
```bash
cd bot
cp .env.example .env
# відредагуйте .env: токен, логін/пароль FSolar, серійник
```
`ALLOWED_CHAT_ID` можна тимчасово лишити порожнім. Після `/start` бот покаже ваш
chat ID, але не відкриє доступ до стану інвертора. Впишіть ID у `.env` і
перезапустіть бота — після цього він відповідатиме лише дозволеним чатам.

Для кількох чатів використовуйте ту саму змінну зі значеннями через кому:

```dotenv
ALLOWED_CHAT_ID=123456789,987654321,-1001234567890
```

Замініть приклади на потрібні ID. Один ID, як у попередніх версіях, теж працює.
Пробіли навколо ID дозволені, дублікати ігноруються; від'ємні ID груп підтримуються.
Нульові ID, порожні елементи (зокрема кома в кінці) та нечислові значення зупиняють
запуск із поясненням помилки. Порожнє значення повністю закриває доступ до даних.

Кожен дозволений чат має окремо надіслати `/start` або натиснути «🔔 Підписатись».
`/stop` вимикає лише його власні сповіщення. Додавання ID не підписує чат автоматично.
Усі дозволені чати бачать той самий інвертор та історію; ID групи відкриває доступ
учасникам цієї групи. Щоб дізнатися ID нового чату, надішліть `/start`: бот покаже
ID навіть при відмові в доступі, не розкриваючи показників інвертора.

Після зміни списку перестворіть контейнер, як описано нижче. Видалені ID втрачають
доступ до команд; доставник прибирає їхні підписки та ненадіслані повідомлення.
Після повторного додавання ID необхідно знову підписатися через `/start`.

### 3. Запустити
**Docker (рекомендовано):**
```bash
docker compose up -d --build
docker compose logs -f
```
**Або без Docker:**
```bash
pip install -r requirements.txt
set -a; . ./.env; set +a        # підвантажити змінні (Linux/macOS)
python src/bot.py
```

Для локального запуску залиште `DB_PATH=bot.db`. Docker Compose автоматично
перевизначає шлях на `/data/bot.db` у постійному томі.

### Час у повідомленнях

Для інвертора в Україні залиште `TIMEZONE=Europe/Kyiv`. Бот використовує
`dataTimeStr` і `timeZone` з відповіді FSolar та показує час у налаштованому поясі.
Параметр часу запиту теж використовує цей пояс, навіть якщо VPS працює в UTC.
Напис `Оновлено` позначає час телеметрії інвертора, тому може відставати на кілька
хвилин. За відсутності придатного часу бот показує `невідомо` і пропускає такий
знімок під час визначення автоматичних сповіщень.

Після оновлення коду перебудуйте контейнер; після зміни `.env` перестворіть його:

```bash
docker compose up -d --build --force-recreate
```

Історичні записи з попередньої версії зберігають свій початковий час.

## Контроль зв’язку та відключення

Після `STALE_AFTER_MINUTES=15` хвилин без актуальних показників бот ставить
одне сповіщення в надійну чергу. Це працює і коли запит завершується помилкою,
і коли FSolar відповідає успішно, але повертає старі дані. Перевірка відбувається
під час опитування та окремим таймером раз на хвилину. Втрата зв’язку не означає
зникнення електрики: у сповіщенні стан мережі позначається невідомим.

Після отримання свіжих даних надходить одне повідомлення про відновлення зв’язку.
Прапорець сповіщення зберігається в SQLite й не скидається при перезапуску.
На першому запуску без жодних даних діє початковий 15-хвилинний період очікування.
Застарілі, майбутні (понад одну хвилину), повторні та старіші знімки не змінюють
стан мережі/заряду й не створюють помилкових переходів. Некоректні знімки без часу
або показників мережі також не використовуються для переходів.

Після відновлення електрики бот показує приблизну тривалість відключення і заряд
на початку та наприкінці. Якщо початок не спостерігався або були прогалини у зв’язку,
це явно зазначається. Відкрите відключення зберігається після перезапуску.

`/outages` рахує епізоди, що перетинаються з місцевим календарним днем/місяцем, і
лише тривалість усередині цього періоду. Незавершене відключення враховується до
останнього спостереження, а не до поточного часу за відсутності даних. Підсумки
приблизні через частоту опитування; періоди з невідомим початком/прогалинами мають
позначку `*`. Детальний облік починається після цього оновлення; старі `/history`
записи залишаються доступними, але не використовуються для відновлення невідомих
тривалостей.

## Графіки

Свіжі унікальні показники заряду і навантаження записуються під час фонового
опитування. За замовчуванням зберігаються 90 днів (`TELEMETRY_RETENTION_DAYS`).
Прогалини понад поріг свіжості та відсутні значення переривають лінії графіка.
Графіки PNG формуються на сервері й надсилаються лише дозволеним чатам.

Історія накопичується від моменту оновлення, без завантаження минулих даних із
FSolar. Спочатку графік може містити одну точку. Зменшення строку зберігання
видаляє давніші **показники для графіків** при наступному свіжому знімку; записи
відключень, підписники та черга повідомлень залишаються. Нові таблиці SQLite
створюються автоматично без очищення наявної бази.

Після оновлення надішліть `/menu`, щоб побачити нові кнопки.

## Деплой (працює всюди завдяки Docker)

| Платформа | Як |
|---|---|
| **VPS** (Hetzner, DigitalOcean…) | `git clone` → `.env` → `docker compose up -d`. Найбільше контролю. |
| **Fly.io / Railway** | Підтримують Dockerfile; задайте змінні оточення в дашборді. |
| **Raspberry Pi** | `docker compose up -d`. ⚠️ Має бути на UPS/захищеному виводі інвертора. |

> ⚠️ **Не хостьте вдома без UPS:** якщо сервер живиться від мережі, він вимкнеться разом зі
> світлом — і ви не отримаєте сповіщення про відключення. Хмарний хостинг надійніший.

## Важливо знати
- **Залежність від звʼязку:** бот бачить відключення, лише поки інвертор шле дані у FSolar.
  Ваш off-grid інвертор на батареї — донгл живиться, але **роутер теж має бути на
  захищеному виводі**, інакше дані не дійдуть до хмари під час відключення.
- **Період:** хмара FSolar оновлюється ~раз на 5 хв — це стеля свіжості; опитуємо кожні 3 хв.
- **Повторна доставка:** невдалі Telegram-повідомлення лишаються у SQLite й повторюються
  кожні 30 секунд, зокрема після перезапуску контейнера.
- **Пороги батареї:** при розряджанні бот сповіщає після переходу нижче 90%, 50% і 25%;
  при заряджанні — після переходу вище 90% і 99%. Пороги не повторюються без нового
  перетину рівня.
- **Напрям батареї:** у FSolar додатна потужність означає заряджання, від'ємна —
  розряджання. У повідомленні показується модуль потужності. Наявність мережі
  не підмінює напрям потоку батареї, зокрема при заряджанні від сонця.

## Безпека

- Облікові дані й токен зберігайте лише в `.env`; файл не комітиться й виключений
  із Docker build context.
- Не залишайте `ALLOWED_CHAT_ID` порожнім після початкового визначення ID.
- Контейнер запускається від непривілейованого користувача.
- FSolar endpoint-и не мають стабільного публічного контракту й можуть змінитися.

## Тести
```bash
pip install pytest && pytest bot/tests -q
```
Покривають логіку переходів мережі та мапінг знімка (grid-on/off, SOC). Запускаються в CI
(`.github/workflows/bot-ci.yml`).

## Як це влаштовано
```
src/
  config.py    — змінні оточення
  fsolar.py    — клієнт FSolar (RSA-логін, snapshot, alarms) + parse_snapshot
  detector.py  — правило переходу мережі
  monitoring.py — свіжість телеметрії, відключення, атомарний запис сповіщень
  charts.py    — графіки PNG заряду і навантаження
  storage.py   — SQLite (підписники, стан, історія, черга доставки)
  bot.py       — команди, полер FSolar і доставник Telegram-повідомлень
```
